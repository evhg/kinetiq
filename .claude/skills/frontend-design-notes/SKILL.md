# Frontend design notes (own summary)

Source read on 2026-10-21: `anthropics/claude-code` → `plugins/frontend-design/skills/frontend-design/SKILL.md`.
That repository is "© Anthropic PBC. All rights reserved", so the original text is not copied here.
These are our own notes on the ideas worth applying to KINETIQ.

## Ideas we apply
- Derive the look from the subject: padel, carbon, moulds, Swiss precision. Not from a generic "premium" template.
- The hero shows the most characteristic thing about the product, in the form that suits it best.
  A big number with a small label and a gradient is a default, not a choice.
- One or two typefaces. If two, clearly different. The type itself is part of the design.
- Line length under about 80 characters.
- Structure carries meaning: numbers only for real sequences, labels only when they add information.
- Spend boldness in one place. One orchestrated moment beats many scattered effects.
- Motion that answers a person's action is good. Decorative entrance on every section is not.
- Plan first (4–6 named colours, type roles, layout sketch, principles), then check the plan against the
  brief and change anything that would come out the same for any similar brief. Then build.
- Critique from screenshots while building. Remove one accessory before shipping.
- Copy: plain, active, specific. Buttons say what happens. Same action keeps the same name.

## Generic tells to avoid unless the brief asks for them
- Warm cream background with a high-contrast serif and a terracotta accent.
- Near-black background with a single acid-green or vermilion accent.
- Newspaper hairlines and dense columns.
- Identical rounded cards with the same soft shadow everywhere.
- Tracked-out all-caps eyebrow above every heading, middle-dot meta strings, arrows appended to links,
  monospace for small labels, tinted near-black standing in for black.

Note: the old reference site (kinetiq-review.vercel.app) used several of these (dark base, red accent,
mono eyebrows, numbered 01/02/03 markers on non-sequences). Treat it as an asset source, not a style guide.
